# Triangle Database

Triangle Database подключает [Illuminate Database](https://laravel.com/docs/database) к приложениям на Triangle Engine 9 и Localzet Server 7. Компонент запускает Eloquent и query builder, регистрирует соединения из конфигурации Engine и связывает пагинацию с текущим запросом.

Текущая версия — [`2.1.0`](https://github.com/Triangle-org/Database/releases/tag/v2.1.0). Она поддерживает Triangle Engine 9, Localzet Server 7 и Illuminate Database 12 или 13. Опубликованная линия `1.x` рассчитана на старые версии Engine и несовместима с этим выпуском.

## Совместимость

| Компонент | Поддерживаемая версия |
| --- | --- |
| PHP | 8.2 или новее |
| Triangle Engine | 9.x |
| Localzet Server | 7.x, устанавливается через Triangle Engine |
| Illuminate Database, Events, Pagination | 12.x или 13.x |
| Symfony VarDumper | 7.4.x |

Engine 8 и более ранние версии эта ветка не поддерживает. При переходе с опубликованной линии 1.x обновляйте компоненты Triangle согласованно и проверяйте lock-файл до выкладки.

Illuminate 12 поддерживает пакет на PHP 8.2 и новее. Для Illuminate 13 требуется PHP 8.3 или новее; Composer выбирает совместимую основную версию с учётом версии PHP, на которой разрешаются зависимости.

## Установка

Установите текущую версию 2.x:

```sh
composer require triangle/database:^2.1
```

Проверьте установленную версию командой `composer show triangle/database`. Перед развёртыванием после обновления с 1.x проверьте lock-файл.

## Настройка соединения

Triangle Engine загружает `config/database.php` при запуске приложения. В комплекте есть шаблон конфигурации с примерами для SQLite, MySQL, PostgreSQL, SQL Server и MongoDB. Храните реквизиты подключения в переменных окружения и включайте только используемые драйверы и PHP-расширения.

Например, выберите MySQL в `.env`:

```dotenv
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=app
DB_USERNAME=app
DB_PASSWORD=change-me
```

`DB_PASSWORD` — пример. Передавайте реальное значение через окружение развёртывания или хранилище секретов. Не коммитьте реквизиты подключения.

Компонент регистрирует выбранное соединение по умолчанию и все именованные соединения из конфигурации. По умолчанию `persistent` равно `true`. Если Engine запускает компонент с экземпляром Server, он добавляет MySQL keepalive-запрос каждые 55 секунд. Установите `persistent` в `false`, если это поведение не требуется. Менеджер и его соединения локальны для процесса: у каждого worker свой менеджер базы данных.

## Eloquent и query builder

Создайте модель приложения на основе модели компонента:

```php
<?php

use Triangle\Database\Model;

final class User extends Model
{
    protected $table = 'users';

    protected $fillable = ['name'];

    public $timestamps = false;
}
```

Затем используйте стандартный API Illuminate:

```php
$user = User::query()->create(['name' => 'Ada']);
$found = User::query()->where('id', $user->id)->first();

$rows = \Triangle\Database\Manager::table('users')
    ->where('name', 'Ada')
    ->get();
```

`Model` компонента наследует модель Eloquent. `Manager` наследует Capsule Manager, поэтому методы соединений, схем и query builder соответствуют API Illuminate. Для raw SQL передавайте значения отдельными binding-параметрами; не вставляйте пользовательский ввод в SQL-строку.

## Пагинация и запуск приложения

Engine загружает `Triangle\Database\Bootstrap` в рамках жизненного цикла компонента. Bootstrap ничего не делает, если соединения не настроены. В противном случае он настраивает Capsule, запускает Eloquent и задаёт резолверы страницы, пути, query string и cursor на основе текущего запроса Triangle.

В обработчике запроса используйте методы Illuminate `paginate`, `simplePaginate` или `cursorPaginate`. Резолверы пагинации — callback-и на весь процесс, поэтому обращайтесь к ним при обработке запроса и не сохраняйте данные запроса в долгоживущем состоянии приложения.

Компонент предоставляет schema builder Illuminate, но не добавляет отдельную CLI-команду миграций и не меняет схему автоматически. Выполняйте миграции в выбранном процессе развёртывания.

## Драйверы и расширения

Доступность драйверов зависит от установленных PHP-расширений и PDO-драйверов. Интеграционный тест компонента использует SQLite в памяти. Для MySQL, PostgreSQL и SQL Server нужны соответствующие PDO-расширения. MongoDB подключается через совместимую установленную интеграцию, если она доступна; локальный тест SQLite не проверяет MongoDB.

## Локальная проверка

```sh
composer install --no-interaction
composer validate --strict --no-check-publish
composer test
```

Интеграционный тест запускает Engine 9 с SQLite в памяти, создаёт таблицу и проверяет запись и чтение через Eloquent. GitHub Actions проверяет PHP 8.2 и 8.5 на минимальных поддерживаемых и последних допустимых зависимостях. Дополнительно Illuminate 12 проверяется на PHP 8.2, а Illuminate 13 — на PHP 8.3 и 8.5, то есть на минимальной и последней поддерживаемой версиях PHP для Illuminate 13. Workflow разрешает версии из `composer.json`, поскольку библиотека не хранит lock-файл. Внешние базы данных и production-реквизиты в CI не используются.

## Безопасность и эксплуатация

- Используйте отдельные учётные записи БД с минимально необходимыми правами и ограничивайте сетевой доступ к базе.
- Не храните секреты подключения в исходниках, логах и ответах с исключениями.
- Отдавайте предпочтение Eloquent и query builder с параметрами. Для raw SQL связывайте каждое значение через bindings.
- Настраивайте таймауты соединения и TLS-параметры согласно требованиям драйвера и окружения.
- MySQL keepalive с интервалом 55 секунд проверяет жизнеспособность соединения, но не является пулом, политикой повторов или гарантией доступности.
- Резервное копирование и изменение схемы выполняйте в процессе развёртывания; компонент не запускает миграции автоматически.
